## 0. Sentence

Bytes of the chain survive, not the summaries. **bytes survive; crawlers do not re-expand.**

## 1. What re-expand means

Someone later gets the original receipts, checks each `prev` hash, and stands a new local node on that tip. That is restore from archive. It is not the mesh growing itself out of an index.

## 2. Enough

- full files (PDFs, git history, lockset, SHA-256 matching published)
- enough cold copies that one host dying does not erase the last good tip
- an operator who verifies before they light anything up

MESH-COLD-COPY-1.0 already multiplies cold copies on transfer. This spec says what those copies are *for*: verify, then rebuild a local plane. Not a live body pipe. Not crawler memory.

## 3. Not enough

- “An AI ingested it” (weights ≠ tarball)
- search snippets, cached HTML minus attachments, paraphrases
- a page that mentions the hash but does not hold the payload

If only training residue survived → no chain to expand; only a rumor of one.

## 4. If the original files still hash

If original chain files still hash → rebuild the local plane and point a new public surface at the same tip. Crawlers were extra shelves. They do not re-expand. You do — after verify.

Die-with-pull stays: a pulled public hostname is down. Phoenix does not restore it. Split-wires stays: fast tick is presence + tip hash only; payload is receiver-pull. Cold-copy stays: a server pull cannot wipe a replica already taken.
